# PRD — 생활 보행환경 지도 서비스

## 1. 개요

### 한 줄 정의

월계1동 주민 참여형 생활 보행환경 지도 서비스

### 제품 목표

고령자, 휠체어 이용자, 유모차 이용자 등 보행약자가 이동 전에 경로 주변의 계단, 단차, 급경사, 좁거나 막힌 보행로, 공사 및 임시 통행 제한 등의 정보를 확인하고 자신의 이동 조건에 맞는 경로를 선택할 수 있도록 한다.

주민이 사진, 조건 점검표, 지도 위치를 활용해 현장 정보를 제보하면 보행환경 데이터가 축적되며, 제보 활동에 대한 포인트를 지역 상점 이용 혜택과 연결해 주민 참여와 지역 상권 활성화의 선순환 구조를 만든다.

### 배경

기존 지도 서비스는 주로 목적지, 거리, 예상 시간, 일반적인 이동 경로를 제공하지만 실제 보행에 영향을 주는 계단, 높은 단차, 급경사, 좁은 길, 적치물, 공사 및 임시 통행 제한과 같은 생활권 환경 정보는 충분히 보여주지 못한다.

이러한 요소는 일반 이용자에게는 단순한 불편 사항일 수 있지만, 고령자, 휠체어 이용자, 유모차 이용자 등에게는 해당 경로를 실제로 이용할 수 있는지를 판단하는 중요한 정보가 될 수 있다.

월계길은 전국 단위의 서비스가 아닌 월계1동을 시작점으로 삼아 주민이 직접 현장 정보를 수집하고 공유하는 생활권 중심의 보행환경 지도를 구축한다.

## 2. 문제 및 해결방안

### 사용자 문제

보행약자는 목적지까지의 거리나 예상 시간만으로는 실제 이동 가능 여부를 판단하기 어렵다. 이동 중 계단, 높은 단차, 급경사, 좁거나 막힌 통로, 공사 구간 등을 마주치면 우회하거나 이동을 중단해야 할 수 있다.

반면 주민이 이러한 보행환경 문제를 알고 있더라도 이를 사진, 위치, 조건 정보와 함께 쉽고 표준화된 방식으로 기록하고 공유할 수 있는 지역 기반 도구가 부족하다.

### 해결 방안

월계1동의 보행환경 문제를 지도 위에 표시하고, 각 제보에 사진, 위치, 보행환경 유형, 통행 가능 여부, 제보 시각 등의 정보를 함께 제공한다. 사용자는 출발 전 또는 이동 중 모바일 웹에서 주변 보행환경 정보를 확인할 수 있으며, 주민은 간단한 조건 점검표와 사진을 통해 현장 정보를 제보할 수 있다.

축적된 제보는 관리자 검토와 상태 갱신을 거쳐 관리하며, 이용자는 지도에 표시된 정보를 바탕으로 자신의 이동 조건에 맞는 경로를 선택할 수 있다.

### 차별점

일반 지도 서비스가 거리와 이동 시간 중심이라면 월계길은 **'이 길을 실제로 이용할 수 있는가'를 판단하는 생활 보행환경 정보**에 집중한다.

월계1동이라는 좁은 생활권을 기반으로 주민이 직접 현장 정보를 제보하고, 계단·단차·경사·통행 폭·공사·장애물 등의 정보를 구조화한다. 또한 제보 활동에 포인트를 지급하고 이를 지역 상점 혜택과 연결하여 정보 생산을 일회성 참여가 아닌 지속적인 주민 참여로 이어지도록 한다.

## 3. 타겟 및 시나리오

### 타겟 사용자

핵심 이용자는 월계1동에 거주하거나 방문하는 고령자, 휠체어 이용자, 유모차 이용자 및 보호자·동행자다. 이들은 외출 전 또는 이동 중 일반적인 거리보다 계단 유무, 단차, 경사, 통행 폭, 공사 및 임시 통행 제한 여부 등을 중요하게 확인할 필요가 있다.

보조 사용자는 월계1동 주민, 지역 활동가 등 생활권을 자주 이용하는 주민이다. 이들은 현장 사진과 조건 정보를 제보하고 기존 정보의 변경 사항을 알려 보행환경 데이터의 최신성을 유지하는 역할을 한다.

운영 측면에서는 서비스 관리자가 제보 검토, 부적절한 콘텐츠 관리, 정보 상태 변경 및 포인트 관리를 담당하며, 향후 지역 상점 운영자는 제보 포인트를 사용할 수 있는 혜택을 제공할 수 있다.

### 사용자 시나리오

1. **출발 전 확인**
   휠체어 이용자가 병원이나 주민센터로 이동하기 전에 모바일 웹에서 출발지와 목적지 주변의 보행환경을 확인하고, 계단이나 급경사 등의 정보를 확인한 뒤 자신의 이동 조건에 맞는 경로를 선택한다.

2. **유모차 이동**
   보호자가 어린이집이나 공원으로 이동하기 전 지도에서 좁은 보행로, 단차, 공사 구간 등을 확인하고 이동에 어려움이 예상되는 구간을 피해 경로를 계획한다.

3. **이동 중 확인**
   고령자가 이동 중 보행이 어려운 구간을 만났을 때 모바일 웹에서 현재 위치 주변의 장애 요소와 통행 가능 여부를 확인하고 이동 방향을 조정한다.

4. **주민 제보**
   주민이 길에서 계단이나 적치물 등 보행에 영향을 주는 요소를 발견하면 현재 위치를 지도에서 확인하고 사진과 조건 점검표를 작성해 제보한다.

5. **정보 갱신**
   공사가 끝나거나 통행 장애물이 제거된 경우 주민이 기존 제보의 변경 사항을 신고하고, 관리자가 확인한 후 지도 정보를 최신 상태로 갱신한다.

6. **참여 보상**
   제보가 검토 및 승인되면 포인트를 지급하고, 향후 누적 포인트를 참여 상점의 할인 또는 혜택으로 사용할 수 있도록 한다.

## 4. 성공·위험 요소

### 핵심 지표

해커톤 기간에는 장기적인 사업 성과보다 핵심 기능이 실제 사용자에게 작동하는지를 검증하는 것을 우선한다.

* 테스트 제보 30건 이상
* 제보 완료율 70% 이상
* 제보 중 사진·위치·조건 정보 포함 비율 90% 이상
* 테스트 사용자의 보행환경 정보 확인율 70% 이상
* 테스트 사용자의 제보 기능 완료율 70% 이상

서비스가 실제 운영 단계로 확장될 경우에는 누적 유효 보행환경 제보 수, 최신 상태가 유지되는 제보 비율, 월간 활성 사용자 수(MAU), 재방문율, 주민 제보자의 재참여율, 포인트의 지역 상점 사용률 등을 추가적인 KPI로 관리한다.

※ 실제 서비스 운영 목표 수치는 MVP 테스트 결과를 바탕으로 조정한다.

### 리스크

1. **부정확한 제보**
   제보 내용이 주관적이거나 실제 상황과 다를 수 있으므로 사진, 위치, 객관적인 조건 점검표를 함께 수집하고 관리자 검토 및 사용자 신고 기능을 제공한다.

2. **오래된 정보**
   공사나 적치물 등의 상황은 빠르게 변경될 수 있으므로 제보 시각과 최근 확인일을 저장하고, 상태 변경 제보를 통해 정보를 갱신할 수 있도록 한다.

3. **특정 지역에 제보 편중**
   일부 구간에만 제보가 집중될 경우 월계1동 전체의 정보가 균형 있게 축적되지 않을 수 있으므로 미제보 지역을 확인하고 지역별 제보 현황과 참여 보상을 관리한다.

4. **서비스 정보를 실제 안전성으로 오인**
   지도에 표시된 정보가 해당 경로의 안전이나 통행 가능성을 보장하는 것은 아니므로 참고용 보행환경 정보임을 명확히 안내하고 제보 시각 및 최근 확인일을 표시한다.

5. **개인정보 노출**
   제보 사진에 얼굴, 차량번호, 주거지 내부 등의 개인정보가 포함될 수 있으므로 사진 등록 시 주의사항을 안내하고 부적절한 사진에 대한 신고 및 관리자 삭제 기능을 제공한다. 상용화 단계에서는 얼굴·차량번호 자동 비식별화 등의 기능을 추가 검토한다.

6. **모바일 웹 접근성 및 성능**
   핵심 사용자인 고령자 및 보행약자가 작은 글씨나 복잡한 인터페이스로 인해 이용하기 어려울 수 있으므로 큰 터치 영역, 명확한 버튼, 높은 가독성, 단순한 화면 구조와 저사양 기기를 고려한 지도 성능을 적용한다.

## 6. MVP 범위

### Must Have

핵심 사용자 경험을 검증하기 위해 다음 기능을 필수 구현한다.

* 회원가입 및 로그인
* 월계1동 지도
* 현재 위치 확인
* 보행환경 제보
* 사진 업로드
* 보행환경 유형 선택
* 통행 가능 여부 선택
* 지도 위치 지정
* 제보 등록
* 등록된 제보의 지도 표시
* 기본 포인트 지급

### Should Have

핵심 기능 구현 후 추가한다.

* 보행환경 유형별 필터
* 제보 상세 화면
* 제보 정보 수정 및 상태 변경
* 내 제보 목록
* 포인트 내역
* 사용자 신고 기능
* 최근 확인일 표시

### Could Have

서비스 확장 단계에서 검토한다.

* 보행환경 정보를 고려한 경로 추천
* 어려운 구간을 회피하는 경로 안내
* 지역 상점 포인트 사용
* 여성 안심길 정보 표시
* 외부 이동 서비스 연계
* 관리자 운영 페이지
* 제보 신뢰도 관리

## 7. 핵심 사용자 흐름

1. **보행환경 확인**

`로그인 → 지도 진입 → 현재 위치 확인 → 목적지 확인 → 주변 보행환경 정보 확인 → 이동 경로 선택`

2. **보행환경 제보**

`로그인 → 제보하기 → 위치 선택 → 사진 촬영/업로드 → 보행환경 유형 선택 → 통행 상태 선택 → 제보 등록 → 관리자 검토 → 포인트 지급 → 지도에 정보 반영`

3. **정보 갱신**

`지도에서 기존 제보 선택 → 상태 변경 신고 → 변경 내용 입력 → 관리자 확인 → 정보 갱신`

## 9. 기술 및 운영 고려사항

모바일 웹을 기반으로 GPS를 활용한 현재 위치 확인, 지도 API, 이미지 업로드 및 저장, 사용자별 제보 및 포인트 데이터 관리를 구현한다.

주요 데이터는 다음과 같이 구성한다.

* User — 사용자 정보
* Report — 보행환경 제보
* Location — 제보 위치
* Image — 제보 사진
* Type — 보행환경 유형
* Status — 제보 및 통행 상태
* Point — 포인트
* Store — 지역 상점

제보 데이터에는 제보자, 위치, 사진, 보행환경 유형, 통행 상태, 상세 설명, 등록 시각, 최근 확인일, 관리자 검토 상태 등을 저장한다.

## 10. 범위 외 기능 (Non-Goals)

MVP에서는 다음 기능을 필수 구현 범위에 포함하지 않는다.

* 전국 단위 보행환경 지도 구축
* 보행 가능 여부를 100% 보장하는 서비스
* AI를 활용한 정교한 위험도 자동 판단
* 공공기관 시스템과의 직접적인 데이터 연동
* 복잡한 외부 이동 서비스 호출 기능
* 완전한 상용 수준의 부정 제보 탐지 시스템
* 완전한 자동 개인정보 비식별화 시스템

위 기능은 서비스 확장 및 상용화 단계에서 검토한다.

## 14. 예상 질문

### 1) 기존 지도 서비스와 무엇이 다른가?

기존 지도는 거리, 시간, 일반적인 이동 경로를 중심으로 제공한다. 월계길은 계단, 단차, 급경사, 좁은 보행로, 공사 등 실제 보행환경 정보를 주민 제보를 통해 수집하고 지도에 표시한다.

### 2) 왜 월계1동부터 시작하는가?

전국 단위 서비스를 처음부터 구축하기보다 특정 생활권을 대상으로 실제 현장 데이터를 충분히 축적하고 사용자 경험을 검증하기 위해 월계1동을 시작점으로 설정한다.

### 3) 제보 정보가 틀리면 어떻게 하는가?

사진, 위치, 선택형 조건 정보를 함께 수집하고 관리자 검토 및 사용자 신고를 통해 부정확한 정보를 관리한다. 또한 제보 시각과 최근 확인일을 표시하여 정보의 최신성을 확인할 수 있도록 한다.

### 4) 주민들이 왜 제보하는가?

제보 활동에 포인트를 제공하고 향후 지역 상점의 할인 및 혜택과 연결하여 주민의 참여가 지역 내 소비로 이어지도록 설계한다.

### 5) 포인트 악용은 어떻게 방지하는가?

MVP에서는 다음과 같은 기본적인 운영 정책을 적용한다.

* 동일 위치의 반복 제보 제한
* 일일 포인트 지급 한도
* 관리자 검토

상용화 단계에서는 계정 인증 및 부정 활동 탐지 기능을 추가 검토한다.

# 기능명세서 — 생활 보행환경 지도 서비스

## 1. 문서 개요

### 1.1 목적

본 서비스는 월계1동의 실제 보행환경 정보를 주민이 직접 제보하고, 이용자가 이동 전에 계단, 단차, 급경사, 좁은 보행로, 통행 불가 구간 등의 정보를 확인할 수 있도록 하는 **생활 보행환경 지도 서비스**이다.

보행환경 정보를 지도에 축적하여 고령자, 휠체어 이용자, 유모차 이용자, 보호자 및 일반 주민이 자신의 이동 조건에 맞는 경로를 선택할 수 있도록 지원한다.

또한 보행이 어려운 구간에 대해서는 향후 **카풀 등 대체 이동수단을 연계**하여 사용자가 보행 외의 이동 방법도 선택할 수 있도록 확장한다.

* GPS 및 지도 API 활용
* 사진 업로드 기능
* 사용자 제보 데이터 저장 및 관리

### 1.3 기능 우선순위

| 우선순위   | 의미                   |
| ------ | -------------------- |
| Must   | MVP에서 반드시 구현해야 하는 기능 |
| Should | MVP 이후 우선적으로 추가할 기능  |

# 월계1동 생활 보행 지도 — 백엔드

주민이 보행 불편 구간을 사진·위치·태그로 제보하고, 누구나 지도에서 확인하는 서비스의 API 서버입니다.
앱 개발자용 API 설명은 [API.md](API.md)를 보세요.

- Node.js 18+ / Express / PostgreSQL 13+
- 사진은 서버 PC의 `uploads/` 폴더에 저장
- 가입: 아이디 + 닉네임 + 비밀번호 (개인정보 미수집), 아이디·닉네임 중복 확인 API 제공
- 제보 등록은 로그인 + 월계1동 반경 1.5km 안에서만 가능, 지도 조회는 누구나

## 실행 방법

1. PostgreSQL을 설치하고 DB를 하나 만듭니다.
   ```
   createdb walkmap
   ```
2. 패키지 설치
   ```
   npm install
   ```
3. `.env.example`을 `.env`로 복사한 뒤 `DB_PASSWORD`, `JWT_SECRET`을 채웁니다.
4. 테이블 생성
   ```
   npm run migrate
   ```
5. 서버 실행
   ```
   npm start        # 또는 개발 중에는 npm run dev
   ```
   `http://localhost:3000/health`가 `{"status":"ok"}`를 돌려주면 정상입니다.

## 서비스 지역 조정

`.env`의 `REGION_CENTER_LAT`, `REGION_CENTER_LNG`, `REGION_RADIUS_KM`로 바꿉니다.
기본 좌표(37.6215, 127.0605)는 월계1동의 대략적인 중심이라, 정확한 값으로 확인 후 수정하는 것을 권장합니다.
테스트할 때 반경을 크게(예: 50) 잡으면 어디서든 제보할 수 있습니다.

## 폴더 구조

```
migrations/        DB 테이블 정의(001_init.sql)와 실행 스크립트
src/index.js       서버 진입점
src/routes/        URL → 컨트롤러 연결
src/controllers/   auth(중복확인·가입·로그인), report(제보), tag(태그)
src/middleware/    auth(토큰 확인), regionCheck(지역 판정), upload(사진 저장)
src/utils/         geo(거리 계산), files(거부된 사진 삭제)
src/config/        DB 연결, 서비스 지역 설정
uploads/           제보 사진 저장 위치
```

## 아직 없는 것 (팀 결정 대기)

- 포인트: `users.points`, `reports.point_awarded`, `reports.points_amount` 컬럼만 있고 적립 로직은 없음
- 제보 승인/중복 판정, 회피 경로 추천, 관리자 페이지
