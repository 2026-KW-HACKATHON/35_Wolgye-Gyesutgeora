## 실행 방법

먼저 백엔드를 켜고, 그다음 화면을 엽니다.

1. **백엔드 실행** — 저장소 맨 위 폴더에서 (`.env` 설정과 `npm run migrate`는 [../../README.md](../../README.md) 참고)
   ```
   npm start
   ```
   `http://localhost:3000/health`가 `{"status":"ok"}`를 돌려주면 정상입니다.
   테스트할 때는 `.env`의 `REGION_RADIUS_KM=50`으로 두면 어디서든 제보할 수 있습니다.

2. **화면 실행** — 저장소 맨 위 폴더에서 새 CMD 창을 열고
   ```
   npx serve -l 5500 frontend/web
   ```

3. 크롬에서 `http://localhost:5500`을 열고 위치 권한을 **허용**합니다.
   폰 화면처럼 보려면 `F12` → 기기 툴바 아이콘 → 폭 390으로 맞춥니다.

파일을 더블클릭해서 열면 위치 권한이 막힐 수 있으니 위 주소로 여는 것을 권장합니다.

## 필터 동작

- 지도 오른쪽 아래 **필터** 버튼 → 통행 상태(통행 가능/불편/불가)와 불편 유형(계단, 단차 등)을 고르는 창이 열립니다.
- 서버에 다시 요청하지 않고, 이미 받은 제보를 화면에서 걸러 냅니다. 버튼을 누르는 즉시 지도가 바뀝니다.
- 규칙: **같은 항목 안에서는 하나라도 맞으면(OR), 항목이 다르면 둘 다 맞아야(AND)** 보입니다.
  예) 통행 불가 + 통행 불편 + 계단 → (통행 불가 또는 통행 불편)이면서 계단이 있는 제보
- 아무것도 고르지 않은 항목은 제한하지 않습니다. **초기화**를 누르면 전체가 다시 보입니다.
- 조건을 고르면 필터 버튼이 파랗게 바뀌고 조건 개수가 표시됩니다. 결과가 0건이면 안내가 뜹니다.
- 통행 상태를 입력하지 않은 옛 제보는 통행 상태 필터를 걸면 보이지 않습니다.
- 규칙은 `js/map.js`의 `matchesFilter`, 화면은 `js/filter.js`입니다.

## 마이페이지

- 로그인하면 상단 바에 **마이페이지** 버튼이 나타납니다.
- **내 포인트**: 로그인 사용자 정보의 `points` 값이고, 열 때마다 `GET /api/auth/me`로 새로 받아서 최신 값을 보여줍니다.
  (제보가 승인되면 서버가 자동으로 포인트를 올려 주므로, 새로고침 없이 다시 열면 반영됩니다.)
- **내 제보 목록**: `GET /api/reports/mine`. 사진(있으면 첫 장), 검토 상태(검토 중/승인됨/반려됨/중복 제보),
  통행 상태, 제목 또는 태그, 등록일을 보여줍니다.
- **범위에 없는 것**: 제보 상태 변경 신고, 포인트로 지역 상점 혜택 이용은 만들지 않았습니다.
  백엔드에도 이 기능의 API가 없어서, 필요하면 백엔드 담당과 먼저 API를 정해야 합니다.

- `role='admin'`인 계정으로만 들어갈 수 있어요. 일반 계정으로 로그인하면 "관리자 권한이 있는 계정이 아니에요."라고 막습니다.
  로컬 DB에서 계정을 관리자로 바꾸는 방법은 발표 준비 메모를 참고하세요(SQL로 `role='admin'` 변경).
- 탭(검토 중 / 승인됨 / 반려됨 / 전체)으로 목록을 보고, 각 제보의 **승인 / 반려** 버튼으로 상태를 바꿉니다.
  승인하면 서버가 포인트를 자동 지급하고, 지급됐으면 "포인트 N점 지급" 안내가 뜹니다.
- 이 페이지는 팀 내부용이라 큰 글씨·큰 버튼 같은 접근성 기준을 적용하지 않았고, 데스크톱 폭에 맞춰져 있습니다.

## 승인된 제보만 표시

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|

| 마커가 하나도 없음 | 정상입니다. 아직 등록된 제보가 없는 것 (제보 기능은 4단계) |
