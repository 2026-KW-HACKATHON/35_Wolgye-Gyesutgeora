# 월계 한걸음 — 웹 프로토타입 (프론트엔드)

주민이 계단·단차 같은 보행 불편 구간을 사진·GPS·태그로 제보하고, 지도에서 확인하는 서비스의 화면입니다.
앱 개발 환경이 정해지기 전까지, 모바일 폭(390px) 기준의 웹 프로토타입으로 진행합니다.

- 지도: Leaflet + OpenStreetMap
- 서버: 저장소 맨 위 폴더의 백엔드 (API 설명은 [../../API.md](../../API.md))
- 별도 빌드 도구 없이 HTML/CSS/JS 파일만 사용합니다.

## 실행 방법

먼저 백엔드를 켜고, 그다음 화면을 엽니다.

1. **백엔드 실행** — 저장소 맨 위 폴더에서 (`.env` 설정과 `npm run migrate`는 [../../README.md](../../README.md) 참고)
   ```
   npm start
   ```
   `http://localhost:3000/health`가 `{"status":"ok"}`를 돌려주면 정상입니다.
   테스트할 때는 `.env`의 `REGION_RADIUS_KM=50`으로 두면 어디서든 제보할 수 있습니다.

2. **화면 실행** — 저장소 맨 위 폴더에서 새 CMD 창을 열고
   ```
   npx serve -l 5500 frontend/web
   ```

3. 크롬에서 `http://localhost:5500`을 열고 위치 권한을 **허용**합니다.
   폰 화면처럼 보려면 `F12` → 기기 툴바 아이콘 → 폭 390으로 맞춥니다.

파일을 더블클릭해서 열면 위치 권한이 막힐 수 있으니 위 주소로 여는 것을 권장합니다.

## 폴더 구조

```
frontend/web/
  index.html       주민용 화면 뼈대와 script 연결
  admin.html       관리자 페이지 (제보 검토)
  css/style.css    주민용 화면 스타일
  css/admin.css    관리자 페이지 전용 스타일 (style.css의 배지·버튼 스타일을 함께 씀)
  js/config.js     BASE_URL(서버 주소), 처음 지도 위치, 마커 색
  js/api.js        서버 호출, 오류 code별 안내 문구
  js/tts.js        음성 읽어주기 (Web Speech API, 서버·API 키 불필요)
  js/map.js        지도, 마커, 팝업, 현재 위치
  js/auth.js       로그인 상태 저장, 상단 로그인 표시, 로그인·회원가입 창
  js/report.js     제보 등록 창, 제보 완료 화면
  js/pick.js       지도에서 점 하나를 직접 고르는 전체 화면 지도 (제보 위치 선택 + 경로 찾기 출발·도착 선택이 함께 사용)
  js/route.js      경로 찾기 창 (백엔드 연동됨, 아래 참고)
  js/filter.js     보행환경 필터 창
  js/mypage.js     마이페이지 (내 포인트, 내 제보 목록)
  js/places.js     장소 검색 (월계 주요 장소 목록 + 인터넷 검색, 검색란과 위치 선택 화면이 함께 사용)
  js/search.js     검색란 (제보 검색, 장소 검색)
  js/points.js     포인트 내역 창 (마이페이지에서 열림)
  js/store.js      지역 상점 창 (포인트 내역에서 열림, POST /api/store/redeem 연동됨 — 상품은 설문 전 예시)
  js/coupons.js    내 쿠폰함 창 (지역 상점에서 열림, 전용 API 없이 포인트 내역의 상점 교환 항목만 모아 보여줌)
  js/flag.js       제보 신고 창 (원래 잘못된 정보 신고·정보 변경 신고 2개였는데 하나로 합침, 서버 저장까지 연동됨)
  js/admin.js      관리자 페이지 로직 (admin.html 전용, 다른 js 파일과 독립적)
  js/main.js       시작점
```

`index.html`은 스크립트를 `config → api → tts → map → places → auth → report → pick → route → filter →
mypage → points → store → coupons → flag → search → main` 순서로 불러옵니다. 앞 파일의 함수를 뒤 파일이 쓰므로 순서를 바꾸면 동작하지 않습니다.
(`pick.js`는 `report.js`의 전역 `position`을 참조하므로 `report.js` 다음, `route.js`보다 앞이어야 합니다.)

## 필터 동작

- 지도 오른쪽 아래 **필터** 버튼 → 통행 상태(통행 가능/불편/불가)와 불편 유형(계단, 단차 등)을 고르는 창이 열립니다.
- 서버에 다시 요청하지 않고, 이미 받은 제보를 화면에서 걸러 냅니다. 버튼을 누르는 즉시 지도가 바뀝니다.
- 규칙: **같은 항목 안에서는 하나라도 맞으면(OR), 항목이 다르면 둘 다 맞아야(AND)** 보입니다.
  예) 통행 불가 + 통행 불편 + 계단 → (통행 불가 또는 통행 불편)이면서 계단이 있는 제보
- 아무것도 고르지 않은 항목은 제한하지 않습니다. **초기화**를 누르면 전체가 다시 보입니다.
- 조건을 고르면 필터 버튼이 파랗게 바뀌고 조건 개수가 표시됩니다. 결과가 0건이면 안내가 뜹니다.
- 통행 상태를 입력하지 않은 옛 제보는 통행 상태 필터를 걸면 보이지 않습니다.
- 규칙은 `js/map.js`의 `matchesFilter`, 화면은 `js/filter.js`입니다.

## 마이페이지

- 로그인하면 상단 바에 **마이페이지** 버튼이 나타납니다.
- **내 포인트**: 로그인 사용자 정보의 `points` 값이고, 열 때마다 `GET /api/auth/me`로 새로 받아서 최신 값을 보여줍니다.
  (제보가 승인되면 서버가 자동으로 포인트를 올려 주므로, 새로고침 없이 다시 열면 반영됩니다.)
- **내 제보 목록**: `GET /api/reports/mine`. 사진(있으면 첫 장), 검토 상태(검토 중/승인됨/반려됨/중복 제보),
  통행 상태, 제목 또는 태그, 등록일, 조회수("N회 조회됨", 2026-10-01 추가)를 보여줍니다.

## 검색란

지도 위쪽(상단 바 아래)의 검색란입니다.

- **제보 검색**: 입력하는 즉시, 지금 지도에 보이는 제보에서 찾습니다. 제목·설명·제보자 닉네임·태그 이름·통행 상태를 대상으로 하며,
  띄어쓰기로 나눈 검색어가 **모두** 들어 있는 제보만 나옵니다. (예: "계단 통행 불가")
  - 필터가 걸려 있으면 필터를 통과한 제보만 찾습니다. (지도에 보이는 마커와 같은 범위)
  - 결과를 누르면 지도가 그 마커로 이동하고 팝업이 열립니다. Enter를 누르면 첫 번째 결과로 이동합니다.
- **장소 검색** (코드: `js/places.js`, 제보 위치 선택 화면과 함께 씁니다): 결과를 누르면 지도가 그 위치로 이동하고 빨간 표시가 찍힙니다.
  - **월계 주요 장소는 바로 검색됩니다.** 광운대학교, 광운대역, 월계역, 월계1·2동 주민센터, 월계초·중·고등학교, 초안산, 월계1동.
    프론트에 내장한 목록(`LOCAL_PLACES`)이라 인터넷·서버 설정과 상관없이 동작합니다.
    좌표는 OpenStreetMap 검색(2026-09)으로 확인한 **대략적인 값**입니다. 장소를 늘리려면 `LOCAL_PLACES`에 한 줄 추가하세요.
    (월계시장 등은 검색으로 좌표를 확인하지 못해 넣지 않았습니다)
  - **목록에 없는 장소**는 결과 아래 **"인터넷에서 더 찾기"**를 눌렀을 때만 OpenStreetMap 검색(Nominatim)을 부릅니다.
    - ✅ **2026-10-01부터 실제로 동작합니다.** 서버가 CSP `connect-src`에 `https://nominatim.openstreetmap.org`를
      허용하도록 바뀌었습니다(프론트 수정 없이 바로 됨). 혹시 네트워크 문제 등으로 실패하면 그때는 실패를
      숨기지 않고 "인터넷 장소 검색을 쓸 수 없어요…"라고 안내합니다.

## 포인트 내역

- 마이페이지 포인트 카드의 **"포인트 내역 보기"** → 현재 포인트, 획득 내역(+), 차감 내역(-)을 보여줍니다.
- 데이터는 `GET /api/points/history`(2026-10-01 백엔드 연동됨, `js/api.js`의 `fetchPointHistory()`)에서 바로 가져옵니다.
  (예전엔 전용 API가 없어서 승인된 제보 상세를 모아 임시로 만들었는데, 그 방식은 제거했습니다.)
- **획득**: 제보 승인(`report_approved`) / 정보 변경 신고 채택(`change_report_accepted`, 30점)
- **차감**: 지역 상점 교환(`store_redeem`)뿐입니다. **지급된 포인트는 승인 취소·제보 삭제로도 회수하지 않습니다**
  (2026-10-02 백엔드가 포인트 회수 기능을 팀 결정대로 되돌림 — 중간에 잠깐 있었던 회수 기능은 완전히 제거됨).
  옛 `approval_cancelled`·`report_deleted` 내역(그 기능이 잠깐 있었을 때 쌓인 것)이 남아 있어도 라벨만 표시합니다.

## 관리자 페이지

- 주소: `admin.html` (예: `http://localhost:3000/admin.html`). 주민용 화면(`index.html`)과는
  **다른 로그인 세션**을 써서(저장 키가 달라요), 같은 브라우저에서 주민 계정 로그인 상태를 건드리지 않습니다.
- `role='admin'`인 계정으로만 들어갈 수 있어요. 일반 가입으로는 관리자가 되지 않고,
  백엔드의 `node scripts/create-admin.js <아이디> <닉네임> <비밀번호>`로만 만들거나 승격할 수 있습니다.
- 큰 탭 3개로 나뉩니다.
  - **제보 검토**: 탭(검토 중 / 승인됨 / 반려됨 / 전체)으로 목록을 보고, 각 제보의 **승인 / 반려** 버튼으로 상태를 바꿉니다.
    이미 승인·반려된 것도 재변경할 수 있고(단, `pending`으로 되돌리는 것은 서버가 막아 둬서 안 됩니다),
    **삭제** 버튼으로 제보를 사진까지 완전히 지울 수 있습니다(되돌릴 수 없음, 확인창 있음).
    승인하면 서버가 포인트를 자동 지급하고, 지급됐으면 "포인트 N점 지급" 안내가 뜹니다.
    - **목록 검색** (2026-09-30 추가): 탭 아래 검색란에 제목·설명·제보자 닉네임·태그·통행 상태로 검색할 수 있습니다.
      서버에 다시 요청하지 않고 이미 받아 온 목록 안에서만 걸러내며(주민용 검색과 같은 방식), 승인/반려/삭제 뒤에도 검색 결과가 그대로 유지됩니다.
    - **제보 수정** (2026-10-01 추가): 각 제보의 **수정** 버튼을 누르면 제목·설명·통행 상태·태그를 바로 고칠 수 있는 칸이
      펼쳐집니다. `PATCH /api/reports/:id`로 저장되며, 검수 상태(승인·반려)·좌표·사진은 이 기능으로 바꾸지 않습니다
      (상태는 승인/반려 버튼, 좌표·사진은 변경 수단 없음 — 심각하게 틀렸으면 삭제 후 다시 제보해야 함).
  - **신고 관리**: "잘못된 정보 신고"와 "정보 변경 신고"를 각각 탭으로 나눠서 봅니다.
    - 잘못된 정보 신고: 대기 중 신고를 **처리 완료 / 기각**으로 표시합니다. (제보 자체의 반려·삭제는 "제보 검토" 탭에서 따로 합니다.)
    - 정보 변경 신고: 신고 사유에 맞춰 통행 상태를 미리 골라 두고, **반영하기**를 누르면 원본 제보의 통행 상태가 실제로 바뀝니다.
      "반영하기" 대신 **기각**도 가능합니다.
    - **대기 중 신고 개수 배지** (2026-09-30 추가): "신고 관리" 탭 옆에 지금 대기 중(`open`)인 신고 개수(잘못된 정보 신고 + 정보 변경 신고 합계)가 빨간 배지로 보입니다.
      로그인 직후와 신고를 처리할 때마다 다시 계산됩니다. 0건이면 배지가 사라집니다.
  - **회원 관리** (2026-10-01 추가, `GET /api/admin/users`): 전체 회원을 아이디·닉네임·포인트·제보 수·가입일과 함께
    목록으로 봅니다. 아이디·닉네임 검색(입력을 멈추면 자동 조회), 역할(전체/일반회원/관리자) 탭, 페이지 나누기(20명씩)를
    지원합니다. **조회 전용입니다 — 회원 정지·탈퇴 같은 처리 기능은 백엔드에 아직 없습니다**(API.md: "정책 결정 후 추가 예정").
- **로그인 만료 처리** (2026-10-02 추가): 관리자 토큰은 7일 유효한데, 만료되거나 무효해진 상태로
  "신고 관리"·"회원 관리"를 보거나 제보를 승인/반려/수정/삭제하려 하면(이 작업들은 토큰을 엄격히 검사함)
  예전엔 "유효하지 않은 토큰입니다."라는 문구만 뜨고 로그인된 화면에 그대로 멈춰 있었습니다. 이제는
  자동으로 로그인 화면으로 돌아가고 "로그인이 만료됐어요. 다시 로그인해 주세요."라고 안내합니다.
- 이 페이지는 팀 내부용이라 큰 글씨·큰 버튼 같은 접근성 기준을 적용하지 않았고, 데스크톱 폭에 맞춰져 있습니다.
- 실제 서버로 전 과정을 검증했습니다: 신고 생성→목록 확인→처리(2026-09-29), 변경신고 생성→반영→제보 필드 갱신 확인(2026-09-29),
  제보 생성→삭제→404 확인(2026-09-29), 제보 수정→원래 값으로 복원까지 확인(2026-10-01), 회원 목록·검색·역할 필터 확인(2026-10-01).
  (검증에 쓴 임시 관리자 계정은 모두 테스트 후 비활성화했습니다.)

## 제보 신고 (주민용)

- 지도 마커 팝업 맨 아래 **"제보 신고"**를 누르면 창이 열립니다. 로그인이 필요합니다.
- **원래 "잘못된 정보 신고"(제보 자체가 처음부터 잘못됨)와 "현장 상황이 바뀌었어요"(제보 이후 상황이 바뀜)를
  버튼 2개·창 2개로 나눠서 만들었는데, "어르신 등 사용자에게 복잡하다"는 2026-09-30 사용자 피드백으로
  하나로 합쳤습니다.** 사용자에게는 신고 사유 하나만 고르게 하고, 그 사유가 둘 중 어느 쪽인지는
  화면 뒤에서 `js/flag.js`가 알아서 판단해 맞는 API로 보냅니다:
  - **"제보 자체가 잘못됨" 쪽** (사진이 이상해요 / 제보 내용이 잘못됐어요 / 이미 있는 제보예요 / 기타)
    → `POST /api/reports/:id/flags`. 관리자가 "처리 완료/기각"으로만 표시합니다(제보 내용 자체는 안 바뀜).
    같은 사람이 같은 제보를 두 번 신고하면 서버가 막습니다(409 `ALREADY_FLAGGED`).
  - **"상황이 바뀜" 쪽** (장애물이 치워졌어요 / 공사가 끝났어요 / 이제 지나갈 수 있어요 / 이제 지나갈 수 없어요)
    → `POST /api/reports/:id/change-report`. 관리자가 "신고 관리" 탭에서 확인한 뒤 "반영하기"를 눌러야
    원본 제보의 통행 상태가 실제로 바뀝니다(신고만으로는 지도가 안 바뀜). 같은 제보를 여러 번 신고해도 막지 않습니다.
- 둘 다 실제로 서버에 저장되고, 관리자 페이지의 "신고 관리"에서 (여전히 각자 다른 탭으로) 확인·처리할 수 있습니다 —
  **화면(주민이 보는 것)만 하나로 합쳤고, 백엔드 API·관리자 화면은 그대로 둘로 나뉘어 있습니다.**

## 경로 찾기

- 지도 오른쪽 아래 **"경로"** 버튼을 누르면 창이 열립니다. 로그인 없이도 쓸 수 있습니다.
- **출발·도착**을 각각 **현재 위치** 또는 **지도에서 선택**(`js/pick.js`의 전체 화면 지도를 그대로 재사용,
  안에서 장소 검색도 됩니다)으로 정합니다.
- 둘 다 정해지면 **경로 찾기** 버튼이 활성화됩니다. `GET /api/route`를 호출해 **TMAP 보행자 길찾기로 계산한
  실제 보행로** 근처의 승인된 제보를 "주의할 구간"으로 보여줍니다(2026-10-01 백엔드 연동, 2026-10-08 직선 대신
  실제 보행로로 개선, 실제 서버로 검증함). 서버에 `TMAP_APP_KEY`가 없으면 `503`으로 "설정 중"이라고 안내합니다.
  경로 반경(`radius_m`)은 직선일 때 과하게 많이 잡히던 문제 때문에 15m로 좁혀서 씁니다(`js/api.js`).
- 결과 화면 위쪽에 경로 길이·주의 구간 개수 요약이 나오고, 각 주의 구간에는 제목(있으면)·통행 상태·태그·거리가 나옵니다.
  경로 주변에 알려진 제보가 20건보다 많으면 가까운 20건만 보여주고 "그 외 N건 더 있어요"라고 안내합니다.
- **"지도에서 보기"**를 누르면 메인 지도에 경로 선과 출발·도착 표시가 그려집니다. 오른쪽 위 **"경로 지우기"**로 없앨 수 있습니다.
- 출발·도착 중 하나라도 서비스 지역 밖이면 서버가 거절합니다(`OUT_OF_REGION`, 제보 등록과 같은 안내 문구 공유).

## 제보 등록 동작

- 제보하기 버튼 → (로그인 안 했으면 로그인 창) → 제보 창이 열립니다.
- **위치는 두 가지 방법으로 정합니다.**
  - **현재 위치**: 창이 열릴 때 GPS로 자동 입력합니다. 실패하면 "다시 확인" 버튼으로 재시도합니다.
  - **지도에서 직접 위치 선택**: 버튼을 누르면 전체 화면 지도가 열리고, 가운데의 빨간 핀이 가리키는 곳을 위치로 정합니다.
    (지도를 움직여 핀을 맞추고 "이 위치로 정하기". 작은 지도를 손가락으로 움직이면 창 스크롤과 부딪혀서 전체 화면 방식으로 만들었습니다)
    GPS를 못 쓰는 환경(권한 거부, http 주소의 폰 등)에서도 이 방법으로 제보할 수 있습니다.
    이 전체 화면 지도 위쪽의 **"장소로 찾기"**에 장소 이름(예: 월계역, 광운대)을 검색하면 지도가 그 근처로 이동합니다.
    (검색은 위 "검색란"의 장소 검색과 같은 방식이며, 이동한 뒤 핀을 정확한 곳에 맞추고 "이 위치로 정하기"를 누릅니다)
  - 직접 고른 뒤에는 "현재 위치로" 버튼으로 다시 GPS 위치로 돌아갈 수 있습니다.
  - 서버는 서비스 지역(반경) 밖의 좌표를 거절합니다(`OUT_OF_REGION`). 이때 떨어진 거리와 허용 반경을 안내합니다.
    지도에서 고른 좌표도 같은 규칙으로 검사됩니다. (서버는 좌표가 GPS인지 직접 고른 것인지 구분하지 않습니다)
- 사진은 1~3장, jpg/png/webp/heic, 장당 10MB 이하입니다. (서버 규칙과 같음)
- 사진은 세 가지 방법으로 추가할 수 있습니다(2026-09-30 복사 붙여넣기·URL 추가함): **① 사진 찍기/고르기 버튼, ② 사진을
  복사한 뒤 제보 창에서 Ctrl+V(붙여넣기), ③ 사진 주소(URL) 입력 후 "추가".** URL 방식은 서버 보안 설정(CSP
  `connect-src 'self'`) 때문에 **외부 주소는 지금 실패합니다** — 실패를 숨기지 않고 안내하며, 복사 붙여넣기를
  대신 권합니다. 같은 서버(localhost:3000) 안의 주소만 실제로 동작합니다. (장소 검색의 "인터넷에서 더 찾기"와 같은 CSP 제약)
- **통행 상태**(통행 가능 / 통행 불편 / 통행 불가)는 **필수, 하나만 선택**합니다. 선택한 값은 전용 칸
  `accessibility_status`와 태그 양쪽에 함께 보냅니다. 지도 팝업에는 색이 있는 "통행 상태" 표시로 나옵니다.
- 나머지 태그(불편 유형)는 1개 이상 선택하고, 서버(`GET /api/tags`)에서 받아 오므로 서버에 태그가 추가되면 폼에 자동으로 나타납니다.
  새 분류(category)가 생기면 `js/report.js`의 `CATEGORY_LABELS`에 제목을 추가하세요. 없으면 "기타"로 묶입니다.
- 서비스 지역 밖이면(`OUT_OF_REGION`) 떨어진 거리와 허용 반경을 안내합니다.
- 등록에 성공하면 제보 완료 화면이 나오고, "지도에서 확인하기"로 새 마커로 이동합니다.
- 포인트는 아직 지급되지 않으며, 완료 화면에는 "승인되면 지급될 예정" 안내만 보여줍니다.
- **N번째 제보 축하 문구**: 완료 화면에 "이 사람의 몇 번째 제보인지" 문구가 함께 나옵니다(포인트 말고도 제보를 더 남기고 싶게 만드는 요소, 2026-09-29 추가).
  - 첫 제보는 "첫 제보를 남겨주셨어요!"처럼 특별히 환영합니다. 5·10·20·30·50·100번째는 🎉와 함께 더 반갑게 알려줍니다. 그 외는 "N번째 제보예요"로 담백하게 안내합니다.
  - 완료 화면이 뜬 직후 `GET /api/reports/mine`(내 제보 개수)을 따로(비동기로) 불러와 채우므로, 완료 화면 자체는 이 요청과 상관없이 바로 보입니다.
    이 요청이 실패해도(네트워크 오류 등) 완료 화면과 포인트 안내는 그대로 보이고, 축하 문구만 조용히 나타나지 않습니다.
  - 로직: `js/report.js`의 `celebrateText()`(문구 결정), `celebrateNth()`(비동기로 채우기), 화면 요소는 `#doneCelebrate`.

## 로그인 동작

- 가입은 아이디 + 닉네임 + 비밀번호이고, 성공하면 바로 로그인됩니다. (개인정보는 받지 않음)
- 규칙: 아이디 영문·숫자·밑줄 4~20자(대문자는 소문자로 저장), 닉네임 2~20자, 비밀번호 8자 이상
- 가입 화면의 "비밀번호 확인" 칸은 입력하는 즉시 일치 여부를 보여주며, 화면에서만 쓰고 서버로는 보내지 않습니다.
- 토큰은 브라우저(localStorage)에 저장되어 새로고침해도 유지되고, 유효기간은 7일입니다.
- 제보하기 버튼은 로그인하지 않았으면 로그인 창을 먼저 띄웁니다.
- 비밀번호 찾기는 없습니다. (본인 확인용 개인정보를 받지 않기 때문)

## 승인된 제보만 표시

지도에는 **승인된(`approved`) 제보만** 표시합니다. (`js/config.js`의 `REPORT_STATUS`)
새로 등록한 제보는 `pending`(검토 중)이라서, 승인되기 전에는 지도에 나타나지 않습니다.
전체를 보고 싶으면 `REPORT_STATUS`를 `''`(빈 문자열)로 바꾸세요.

아직 관리자 승인 화면·API가 없어서, 승인은 DB에서 상태를 직접 바꿔서 합니다. (`reports.status`를 `approved`로)

## 오류 처리

| 상황 | 화면 동작 |
|---|---|
| 서버에 연결 안 됨 / 지도 데이터 로딩 실패 | 안내와 **다시 시도** 버튼 (`main.js`의 `loadMapData`) |
| 위치 권한 거부 / 위치 확인 실패 | 지도는 기본 위치(월계1동)로 계속 사용, **내 위치** 버튼으로 재시도 |
| 지도 그림(타일) 로딩 실패 | 한 번만 안내 |
| 팝업 사진 로딩 실패 | "사진을 불러오지 못했어요" 표시 |
| 로그인 실패, 가입 중복·형식 오류 | 해당 입력칸 아래에 안내 |
| 로그인 만료 | 로그인 창 다시 표시 (제보 작성 내용은 유지) |
| 서비스 지역 밖 제보 | 떨어진 거리와 허용 반경 안내 (`OUT_OF_REGION`) |
| 사진 형식·용량 오류 | 서버 규칙(jpg/png/webp/heic, 10MB)과 같은 기준으로 미리 안내 |
| 제보 등록 실패 | 오류 안내 후 작성 내용을 유지한 채 다시 등록 가능 |

오류 코드별 문구는 `js/api.js`의 `ERROR_MESSAGES`, `errorMessage()`에서 관리합니다.

## 음성으로 듣기 (barrier-free)

- 지도 마커 팝업에 **"🔊 듣기"** 버튼이 있습니다. 누르면 통행 상태·불편 유형·설명을 소리로 읽어줍니다.
  (등록일·제보자는 읽지 않습니다 — 굳이 들을 필요가 없다는 판단)
  시각적으로 글씨를 읽기 어려운 분(고령자, 저시력자 등)을 위한 기능입니다.
- 브라우저 내장 기능(Web Speech API `SpeechSynthesis`)만 써서 **서버·API 키가 필요 없습니다.**
  코드는 `js/tts.js`에 있고, `makeTtsButton(문장)` 하나로 다른 화면에도 쉽게 추가할 수 있습니다.
- 이 기능을 지원하지 않는 브라우저에서는 버튼이 아예 나타나지 않습니다(조용히 숨김, 오류 없음).
- 읽는 도중 같은 버튼을 다시 누르면 멈추고, 다른 곳에서 새로 읽기 시작하면 이전 것은 자동으로 멈춥니다.
  팝업을 닫아도 멈춥니다.
- 한국어 음성은 기기·브라우저에 내장된 것을 씁니다(Windows, 안드로이드, 아이폰 대부분 지원). 없으면 자동으로 숨겨집니다.

## 지역 상점 — 포인트 사용 (완료, 상품은 설문 전 예시)

- 마이페이지 → 포인트 내역 → **"지역 상점 보기"**를 누르면 열립니다. 로그인이 필요합니다.
- 2026-10-02: 기획팀의 **"월계 한걸음 지역상점 포인트 제휴 기획안"**(PDF)을 받아 예시 상품을 그 문서 기준으로 맞췄습니다.
  - 기획안은 포인트 제휴 방식 후보 3가지(①포인트만큼 금액 할인, ②구간별 할인쿠폰, ③구간별 상품·서비스 제공)를
    지역상점 사장님 설문에 부쳐 그 결과로 하나를 고르기로 돼 있고, **아직 설문 전이라 방식이 확정되지 않았습니다.**
  - 그래서 `js/store.js`의 `STORE_ITEMS`는 세 후보 방식 각각의 50P 구간 예시(기획안에 적힌 금액 그대로)를
    나란히 보여주도록 맞췄습니다. 설문 결과가 나오면 이 배열을 그 방식 하나(+ 실제 제휴 상점 정보)로 교체하면 됩니다.
    백엔드의 같은 상수(`storeController.js`의 `STORE_ITEMS`)도 같이 바꿔야 합니다(`item_id` 기준으로 서로 맞춰져 있음).
  - 기획안 지침대로 화면 제목에 **"DEMO"** 배지를 달고, 안내문에도 "가상 상점"이라고 명시했습니다.
- **"교환하기"는 `POST /api/store/redeem`을 실제로 호출해 포인트를 차감합니다** (2026-10-02 백엔드 연동, 실제 서버로 성공·실패 경로 모두 확인함).
  - 요청: `{ item_id }` → 성공 `{ user: { points, ... }, redemption: { item_id, item_name, cost, created_at } }` (받은 `user.points`로 화면이 즉시 갱신됩니다)
  - 실패: `404 ITEM_NOT_FOUND`(없는 상품) / `400 INSUFFICIENT_POINTS`(포인트 부족, `points`·`required` 포함) / `401`(로그인 만료)
  - 교환 내역은 `GET /api/points/history`에 `type: "spend"`, `reason: "store_redeem"`으로 쌓이고, 포인트 내역 화면의 차감 목록에 상품명과 함께 보입니다.
- 가진 포인트보다 비싼 상품은 "포인트 부족"으로 표시되고 버튼이 눌리지 않습니다(클라이언트에서 미리 계산, 서버도 한 번 더 확인함).
- **내 쿠폰함** (2026-10-02 추가, `js/coupons.js`): 지역 상점 화면의 **"내 쿠폰함 보기"**를 누르면 교환한 혜택을 목록으로 보여줍니다.
  전용 API는 없고, `GET /api/points/history`의 `type: "spend"` 항목만 걸러서 상품명·포인트·날짜·제시용 코드(내역 id 앞 8자리, 서버 검증용은 아님)로
  보여줍니다. 교환 방식이 설문으로 확정돼도 이 화면은 그대로 쓸 수 있습니다.
- 2026-09-30 팀 결정: 실제 상점 제휴가 아니라 **가상 상점(데모)으로 구현**하기로 합의됨(기획·디자인 팀 피드백) — 위 기획안으로 공식화됨.

## 조회수 표시 (제보 늘리기 아이디어)

- 팝업 아래쪽 날짜·닉네임 줄에 **"N회 조회됨"**이 함께 나옵니다(0회면 표시 안 함).
  ("N명이 봤어요"가 아니라 "N회 조회됨"으로 쓰는 이유: 사람 수가 아니라 사용자·일 단위 조회 횟수라서 — 백엔드 문서 권장 문구)
- 지도 목록 API(`GET /api/reports`)의 `view_count`를 우선 보여주고, **팝업을 열 때마다 `POST /api/reports/:id/view`를
  실제로 호출해 집계합니다** (2026-10-01 연동). 같은 사람이 하루에 여러 번 열어도 서버가 1회만 반영하므로,
  호출은 안전하게 반복해도 됩니다. 서버가 돌려준 최신 값으로 열려 있는 팝업도 바로 갱신됩니다.
  (실패해도 조용히 무시 — 조회수 집계는 팝업을 보여주는 데 필수가 아니라서)
- 포인트 말고도 "내 제보에 관심이 있구나"를 보여줘서 제보를 더 남기고 싶게 만드는 요소입니다(N번째 제보 축하와 같은 목적).

## 마커 색 규칙

| 색 | 의미 | 태그 분류 |
|---|---|---|
| 주황 | 물리적 장애 | physical (계단, 단차, 급경사 등) |
| 황색 | 임시 장애물 | temp (공사 중, 적치물) |
| 초록 | 여성 안심길 | safety_path |
| 회색 | 그 외 | 조명 불량 등 (색 미정) |

태그가 여러 개인 제보는 **물리적 > 임시 > 안심길** 순서로 색을 정합니다.

## 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| "서버에 연결할 수 없어요" 안내 | 백엔드가 켜져 있는지, `BASE_URL`이 맞는지 |
| 파란 현재 위치 점이 안 보임 | 위치 권한 허용 여부, `http://localhost:5500`으로 열었는지 |
| 화면이 예전 그대로 | `Ctrl + Shift + R`로 강제 새로고침 |
| 마커가 하나도 없음 | 정상입니다. 아직 등록된 제보가 없는 것 (제보 기능은 4단계) |
